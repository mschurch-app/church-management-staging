# 同工帳號與權限：整理操作順序

## 新的設定方式

頁面分為「待審申請」與「同工名單」。有待審申請時優先顯示待審，沒有時顯示名單；使用者切換後不被背景載入結果切回。名單可依姓名／職稱、堂會及啟用狀態篩選；每位同工保留一個「設定」入口，LINE 身分尚待核對者另保留核對入口。

編輯時只顯示一位同工的設定，依序：

1. 基本資料：姓名、職稱與啟用狀態。
2. 事工分工：保留實際職位、主責與共同參與。領域以目前主責摘要顯示，點開才修改；共同參與、跨領域統籌與工作提醒逐層展開。
3. 可使用功能：先顯示已開啟的功能，未使用功能收在「加入其他功能」。每項已開啟功能下面才有「操作權限」，需要時展開查看／新增／修改／刪除／匯出／審核／管理設定。

最後按「儲存同工設定」，沿用同一個原子儲存 RPC 與重試 request ID。首頁排列、舊登入身分資訊、主日服事協調範圍及移除權限放在相應進階區，不與日常設定混列。取消或返回時，如有未儲存輸入先確認是否放棄。

移除的介面：Email 寄送邀請、直接 Email 授權、重寄邀請、每張名單卡片重複列出所有堂會的授權細項與移除按鈕，以及所有未選功能攤開的操作矩陣。保留既有帳號、身分連結、登入相容 API、權限與稽核資料；沒有刪除正式資料。

## 權限與資料保持

- 帳號啟用、角色與功能、細項操作、首頁常用、提醒類型、事工領域及 work_profile 仍依原有伺服器驗證一次儲存；沒有 DDL 或正式業務資料寫入。
- 事工主責與功能權限分別說明，沒有因顯示事工名稱就新增功能權限。財務會計群組與 canonical identity 仍依原本規則檢查。
- 已有操作紀錄照原值帶入；舊帳號沒有細項紀錄時沿用舊相容預設。新增一項原本未授權的功能，起始只有「查看」，需要的新增／修改等由管理員明確勾選。
- 增減其他功能不再重設正在編輯的操作勾選；暫時取消後再勾回也保留本次選擇，未選功能不會送入儲存 payload。
- 擁有者固定啟用與完整權限，不呈現一般帳號的可移除功能清單。
- 精簡 work_profile 僅由本頁傳入 compact 選項。其他入口沿用原模式，已回歸財務會計主責／共同參與與工具權限過濾。

## 視覺與操作

沿用共用表頭、系統字體與語意色。新增樣式限定同工帳號管理頁，表單依 390／1440 CSS px 調整，主要下拉選單至少 48px。待審與名單可用鍵盤方向鍵切換；手機開啟設定將焦點移入設定區，不自動彈出文字鍵盤。閒置透明提示加上 visibility 保護，避免 Safari 留下空白半透明浮層。實際錯誤與載入狀態由原流程呈現，不用百分比猜進度。

本頁、共用分工與審核模組、引用及 shell cache 使用 `20261022-accounts-layout1`；其餘未變更的 Auth 與恢復模組保留各自既有版本。

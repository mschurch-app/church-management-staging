# 教會 OS 第十四、十五階段：衝突草稿的檢視與副本

基準：正式 `a0c4b2b1c461e1cde0f11f3b289703ce4d0df239`（#246）。使用者要求連續完成兩個階段；本輪接續第十、十三批明列的「衝突草稿沒有匯出動線」，先處理信息，再接入排班。兩階段均已完成本機實作與驗證，合併交付，尚未發布。

## 第十四階段：信息草稿副本

- 信息工作室增加「取回本頁內容」與「查看裝置草稿」。尚未填完主題、投影片標題等必填項目，也能先取回內容；正式儲存仍走原驗證與版本鎖，不放寬送出門檻。
- 共用唯讀浮窗可全選文字、下載文字副本，或下載包含完整欄位的 JSON 副本。內容用 textarea value 呈現，不解析為 HTML；下載名稱移除路徑及控制字元。
- 原正式信息已有新版本、被刪除，或正式儲存遇到衝突時，仍可依目前帳號／堂會權限取回自己的有效裝置副本或本頁輸入。檢視及下載不套用、不合併、不改寫正式版本，也不更新裝置 revision。原先恢復流程仍拒絕版本不符的草稿。
- 開啟及每次下載都重新走伺服器使用者／權限核對，要求同一登入與匯出權限；下載前檢查裝置 revision／到期或目前頁面內容。登出、撤權、來源被替換、取消浮窗或等待中的下載完成較晚，均不產生舊內容下載。
- 完整檔保留信息內容及必要的來源欄位，不加入使用者、session、裝置 revision 等本機存放識別。文字檔供人工閱讀；完整檔沒有自動匯入功能。

第十四階段程式先以本機提交 `f23247e` 保存；最終手機布局再於第十五階段交付前補驗，沒有把中間提交當成已部署。

## 第十五階段：排班草稿副本

- 排班編輯表單及裝置續填卡片接入同一套唯讀浮窗。副本依 M＋／火樂顯示堂會與當下服事項目名稱；未填日期、未安排姓名也可取回。
- 原排班內容、是否存在或顯示項目已改變時，副本可供人工核對，既有恢復仍維持指紋及可見欄位檢查，不自動套用舊安排。舊自訂欄位保留其項目 key，移除名稱時需人工辨識。
- 裝置欄位限制為當前堂會已知項目及既有自訂項目格式，字數／型別／數量另行檢查；不把任意本機物件或未知私有欄位放進副本。
- 開啟及下載重新核對排班匯出權限、登入、堂會及來源 revision。正式保存失敗後仍能取回本頁內容；查看副本不啟用裝置保留、不清除未儲存標記、不發送排班或通知。
- 身分失效時立即關閉副本及隱藏排班；開啟副本期間接入穩定忙碌標記與原有控制鎖定。浮窗關閉後回到目前可用的來源按鈕，支援清單重新建立後的焦點還原。
- 順手修正有資料排班的草稿說明、範圍摘要及角色標籤對比，限定於排班頁並沿用共用 secondary 色。手機副本操作改為兩欄，減少四個操作各占一列的高度。

共用浮窗使用原生 dialog、背景捲動鎖定、Escape、焦點還原及至少 44 px 控制；輸入文字隨根字級放大。共用 JS／CSS 與信息模組沿用本次尚未發布的 `experience14` 引用，排班引用及最後 shell cache 為 `experience15`，Worker 同時收錄全部新資源；保留先前資源。沒有變更資料庫、SDK、登入契約、模型或通知規則。

## 限制與待驗收

- 副本供人工保留與比較，沒有新增自動合併、匯入或跨登入恢復。原有 24 小時期限、單一裝置草稿、瀏覽器儲存空間限制仍適用；下載檔需由同工妥善保管，沒有額外加密。
- 開啟及下載需要連線確認當前權限；身份／權限無法確認時不開啟副本。刪除正式資料後取回的是同一登入的既存裝置副本，不是恢復被刪除的正式紀錄。正在下載期間被撤銷但尚未反映在權限回應的服務端時間窗，仍受既有驗證機制限制。
- Mac Safari 原生下載觸發網站授權提示，本輪取消，沒有新增網站下載權限；沒有宣稱原生檔案已落地。Chromium／WebKit 自動化則有讀回實際下載檔案並核對內容。Safari 浮窗內的輔助使用樹在目前自動化工具中沒有穩定提供內容，已用可見畫面驗證操作；讀屏及完整鍵盤環境仍待實機驗收。
- iPhone 17 主畫面 App、Safari／LINE 入口、實體鍵盤、讀屏、弱網及正式多人工作仍待驗收。沒有宣稱全站實機達 99%。

依 OpenAI Docs 的[選型建議](https://developers.openai.com/api/docs/guides/model-selection)，本輪以實際品質檢查判斷配置是否足夠；兩階段已用目前智慧體完成，沒有變更智慧體或應用內 AI 模型。依 Supabase 技能核對 [Auth 訂閱](https://supabase.com/docs/reference/javascript/auth-onauthstatechange) 與 [getUser](https://supabase.com/docs/reference/javascript/auth-getuser)，沿用既有伺服器身分驗證，callback 只處理同步失效及排入清理，不等待 Auth 方法；已讀當日 changelog，沒有 SDK／傳輸設定升級。

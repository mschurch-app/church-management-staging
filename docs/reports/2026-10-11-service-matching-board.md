# 主日服事智能配對工作台

## 調整原因與範圍

使用者授權開始執行先前討論的服事配對介面，採「按主日排班」為主要視角。既有配對以逐筆勾選呈現，缺額、正式人員與同工負擔不容易辨識。本次更改既有主日服事登記管理頁，沒有新增獨立路由。

- 主視角先選主日，顯示當週服事卡、已排人數與缺額。以日期選擇區概覽整季，避免整季名單同時展開。
- 接待一／二與歌手一／二／三合併成「接待」「歌手」卡片，技術職務與正式欄位對應保留。
- 另提供同工服事量、相鄰兩週提醒、待協調事項，以及月份／類別篩選。
- 以本人登記日期、服事項目與本季已排主日數產生建議。可選人數較少的名額先處理；所有結果仍由領袖確認。
- 建議人員可暫留空缺、重新挑選同名額已登記的人選。候補／待回覆只顯示狀態，須依原遞補流程完成確認。
- 正式班表原安排保留；原名額已有正式人員時不自動追加或替換。不同技術名額的意願不互相挪動。
- 預排不儲存個資到瀏覽器儲存區；確認套用才會呼叫原儲存介面。離開／切換季度保護未儲存預排。
- 不確定的儲存結果顯示重新載入動線，避免再次送出。

## 資料與權限

正式專案：`aqanuwilmvdtlzuqlrau`。

資料庫 migration：`20261010160013_service_matching_board.sql` 已套用。

- `get_service_signup_match_context` 沿用既有管理權限查核，依負責類別回傳整季正式安排，取代原本僅載入前 100 筆班表的方式。
- 跨類別衝突在後端計算，只回傳相關登記 ID 的阻擋狀態，不回傳其他領袖類別的人員名單。
- `service_signup_apply_smart_match` 仍查核有效帳號、堂會、季度、負責類別與登記狀態；在鎖定資料後重新檢查最新班表、同日服事和名額。
- 同名的正式安排可能無法區分不同會友，沿用正式班表姓名文字契約並保守阻擋衝突；沒有更動會友或正式欄位識別。
- 既有名單不覆寫，失效登記使整筆交易回復，跳過的衝突回報未代入筆數。
- 本次只部署功能定義，沒有替同工實際套用預排、改寫現有班表或寄送通知。

## 共用框架與版本

沿用系統字體、Church OS 管理後台暖紅配色、共用 SVG 圖示、語意色與操作確認。樣式限定在配對工作區；手機單欄、Mac 雙欄，按鈕至少 44 CSS px，支援減少動效與原生 dialog 鍵盤焦點。

`service-signup-admin.html`、管理模組、工作台模組／樣式及 App Worker 統一 `20261010-match-board1`。Worker 更新只用於資源更新，不更動其他功能。

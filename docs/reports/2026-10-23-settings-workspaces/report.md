# 教會 OS：五個設定工作區優化

日期：2026-10-23。本機實作與驗收完成，等待本批發布授權。

## 五項改善

| 工作區 | 本批改善 |
| --- | --- |
| 教會設定 | 保留依權限分組與搜尋，增加固定重新載入入口、編輯草稿保護、實際保存回饋、保存成功但重讀失敗的恢復動線。無可用工具與權限讀取失敗分別顯示。 |
| 功能與表單呈現 | 上下按鈕支援觸控與鍵盤排序，維持移動後焦點；保留未顯示的功能與已存順序。分區儲存失敗保留尚未完成內容，重試略過已確認儲存的堂會。 |
| 通知設定 | 桌面雙欄卡片、手機單欄、通知項目搜尋；管道與 LINE 接收者逐卡儲存，保留其他卡片的草稿。修正舊 App 通知文案。 |
| 審核流程 | 初審與複審分步呈現，顯示 LINE 綁定狀態；防止同一位同工初複審、尚未綁定的審核人選，並核對後端實際保存回覆。 |
| 系統狀況 | 分區導覽、背景暫停更新、排程操作確認與寫入鎖定；失敗清除舊操作。圖表增加圖例、圖紋及完整數值表，修正第二組長條被舊樣式遮白。 |

五頁沿用共用系統字體、正常 164 px 表頭、44 px 主要控制、M+ 深綠與火樂磚紅。系統監控的狀態列、數字及長條一併依堂會品牌呈現；成功／警示沿用語意色。

## 通知原則與適用範圍

- M+ 既有業務通知項目儲存時使用 LINE，App 開關關閉；未辨識的系統管理項目保持唯讀。App 系統更新與系統狀態通知不在本批業務設定寫入範圍。
- 火樂的通知與審核設定保持唯讀，系統監控中的火樂通知排程不可重新啟用，配合使用者先前指定的「火樂不通知」。
- 原有審核儲存 RPC 要求至少一種通知管道，因此本批未開放火樂審核人選修改；將來如需修改，須先提供支援零通知的後端設定流程。
- 正式通知設定仍以伺服器現存值為準，使用者按儲存後才套用對應設定。本次僅使用合成 API 驗證；沒有重送通知、改寫正式路由、切換正式排程或寄送 LINE。

## 儲存、權限與恢復

`settings-workflow.mjs` 沿用草稿確認及控制鎖定工具。一張卡片保存成功只清除自己的草稿；搜尋與切換表單分頁保留未完成內容。重新載入前確認放棄，送出期間阻止重複請求與離頁。

布林 RPC 回傳 `true`、審核 RPC 回傳 `saved: true`、資料更新回傳單筆紀錄後才顯示成功。缺少確認或網路結果不明會停用再次送出，提供只讀重載核對。已確認保存但重讀失敗會明示已保存。登入變更清除工作區，忽略晚到回應。

沿用原有權限、資料表、堂會條件及版本比對。功能與表單設定原有的跨堂會儲存不是單一交易；本批明示部分完成，重試略過已確認部分。草稿保護限目前頁面，不提供關閉 App 後的持久恢復。

## 驗收

- **992 項隔離檢查通過，0 失敗**，涵蓋 Chromium／WebKit、390／1440 px、M+／火樂，共 40 組頁面環境。
- 版面包含表頭、控制尺寸、實際文字對比、200% 根字體與桌面 1280／1920 px。操作按各頁適用範圍檢查排序、LINE 參數、草稿、重複點擊、失敗恢復、部分保存、版本衝突、權限拒絕、登出後晚到回應。
- 完整測試 952 項後，功能表單的 328 項補驗與監控的 192 項重驗取代相同頁面情境，合計 992 項；未重複累計。
- 固定 **15 組驗收全部通過**，另有 210 個前端程式語法檢查。保留初次失敗與修正後執行紀錄。
- 固定設定回歸保留原權限、儲存與恢復斷言；重新載入入口改用固定按鈕。審核回歸增加火樂唯讀及 M+ LINE 實際參數斷言，並修正 OPTIONS 預檢誤計寫入。
- 初輪發現並修正選取懸停對比、部分移除控制尺寸、WebKit 原生下拉尺寸、狀態標記與空工具說明；畫面審閱另修正圖表第二組長條。

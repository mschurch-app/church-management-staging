# 教會 OS iPhone 17 與 Mac 驗收基準

日期：2026-10-09

## 使用者要求

教會 OS 及兩個教會網站的後續功能開發及頁面設計，手機以 iPhone 17、桌面以 Mac 的使用操作、回饋與頁面呈現為主要基準，品質目標至少 99%。教會 OS 保留常用功能每列三顆、統一自製圖示、簡潔精緻的教會 OS 設計。

這份文件記錄後續執行標準，目前未完成全部實機驗收，也尚未取得 99% 成績。

## 如何計算 99%

每次發布前，固定頁面、角色、堂會、操作與情境的驗收清單，每項記錄預期結果、實際結果、裝置／iOS 版本與證據。

通過率＝通過項目數 ÷ 本次所有必驗項目數。未執行及未取得所需實機證據的項目不計為通過；重複執行同一項不增加分母。排除項目須說明原因，不得在測試後移除失敗項目。

整體必驗項目通過率須達 99%，登入與身分、權限隔離、資料儲存、管理權限變更、審核與發布等核心流程須全部通過。任何造成資料錯亂、未授權操作、空白頁或阻斷核心工作的問題，均阻擋發布。

外觀由事先固定的版面與互動檢查項目驗收；評分時保留截圖及操作錄影。99% 是驗收目標，須在完成檢查後才能回報達成。

## 主要驗收環境

- 真實 iPhone 17，記錄實際 iOS 版本、文字大小、顯示縮放與網路條件。
- 分別驗收加入主畫面的教會 OS、Safari、LINE 內開啟的會友服務；三種登入及返回路徑分別記錄。
- Mac 桌面以 Safari 為優先驗收瀏覽器，Chrome 為相容性驗收瀏覽器；記錄 macOS、瀏覽器版本、視窗大小、縮放及輸入方式。
- 先以 1280、1440、1920 CSS px 視窗寬度檢查，再於實際 Mac 視窗及外接螢幕驗證。這些是測試視窗尺寸，不代表指定 Mac 型號。
- 桌面模擬用於快速版面與程式回歸，真機項目仍需 iPhone 或 Mac 證據。
- 較小／較大 iPhone、Android、其他桌面環境保留相容性檢查。

Apple 列出的 iPhone 17 為 6.3 吋、2622 × 1206 實體像素，具有 Dynamic Island 與最高 120Hz 的適應更新率。網頁版面使用實機測得的可用 viewport 及安全區域，不能把實體像素直接當作 CSS 寬高，也不能據此宣稱網頁動效能維持 120fps。[Apple 技術規格](https://www.apple.com/iphone-17/specs/)

## 頁面與操作要求

| 範圍 | 驗收條件 |
| --- | --- |
| 頁面骨架 | 共用表頭、底部導覽及頁面間距；適應安全區域，不被系統頂部、Home 指示列或鍵盤遮住。正常字體使用一致高度，大字模式依內容調整。 |
| 功能入口 | 常用每列三顆；圖示樣式一致。每個已授權功能均可在常用或收納盒找到，移除、加回及排列後仍正確。 |
| 文字與配色 | 使用系統字體與一致層級。一般文字對比至少 4.5:1、大字至少 3:1；放大文字後不截掉重要內容與操作。 |
| 點擊範圍 | 主要可點擊控制至少 44 × 44 CSS px；包括移除、加入、關閉與圖示按鈕。視覺圖示可以較小，實際可點區域須足夠。 |
| 操作回饋 | 按下即有視覺回饋，目標 100ms 內呈現。需要等待時顯示真實狀態，完成與失敗由實際結果決定；純導覽不顯示資料送出。 |
| 表單與鍵盤 | 正確的輸入類型、下一步與完成動線；錯誤指出欄位，失敗保留已填內容。鍵盤開啟後能看見目前欄位和必要操作。 |
| 浮窗與滑動 | 浮窗內可正常捲動、背景鎖住；滑動不穿透，不意外關閉通知。關閉後回到原本頁面位置。 |
| 長按與拖曳 | 長按進入排列，正常滑動不誤觸；拖曳有清楚目標與完成操作。移除只影響常用，授權與收納入口保持正確。 |
| 動效 | 動效不中斷操作、不造成明顯跳動；遵循系統「減少動態效果」。不以瀏覽器未支援的震動回饋作為必要提示。 |
| 登入與恢復 | 驗證全新登入、取消、授權返回、背景恢復、關閉重開、過期與失敗重試。LINE 登入自動返回原 App 的需求另以實機技術驗證記錄結果。 |
| 網路與資料 | 斷線、慢網路、重複點擊、請求逾時均有可恢復動線；儲存結果一致，重試不產生重複登記、寄送或發布。 |
| 權限與堂會 | 同一角色的入口與實際操作權一致；M+／火樂隔離，無權限的資料不能由直接連結或 API 取得。 |

44 點的原生觸控設計參考 Apple；Web 控制採 44 CSS px 的觸控範圍要求。[Apple 設計建議](https://developer.apple.com/design/tips/)、[W3C 觸控範圍](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)

文字對比門檻依 W3C 準則；減少動效依 WebKit 的 Web 支援方式實作。[文字對比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)、[WebKit 動效設計](https://webkit.org/blog/7551/responsive-design-for-motion/)

## Mac 桌面操作要求

| 範圍 | 驗收條件 |
| --- | --- |
| 版面 | 依可用寬度提供清單、詳情及工作區；限制閱讀區寬度，大表格與排班可使用較寬區域。避免把手機版整頁等比例放大。 |
| 導覽 | 共用功能名稱與分類；依桌面工作方式安排導覽及工具列，保持目前功能與選取項目清楚。 |
| 鍵盤 | Tab／Shift+Tab 可依合理順序操作，焦點可見；Enter 可執行適當操作；Escape 關閉可關閉的浮窗。浮窗開啟時管理焦點，關閉後還原。 |
| 滑鼠與觸控板 | 游標、懸停與選取狀態一致；捲動正常，拖曳不誤開功能；重要操作可由點擊及鍵盤完成。 |
| 視窗變化 | 視窗縮小、放大、文字縮放及外接螢幕時，重要內容與控制均可使用。表格的水平捲動限制在表格區。 |
| 浮窗 | 桌面浮窗使用適當最大寬度，長內容在浮窗內捲動，背景與焦點鎖定；主要動作與關閉位置穩定。 |
| 檔案與列印 | 上傳、下載、檔名、圖片預覽及列印在 Mac Safari／Chrome 分別驗收；依實際結果回饋狀態。 |

以上為本專案採用的 Mac 驗收要求；平台設計參考 [Apple macOS 設計指南](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)。

## 兩個網站的美觀與內容驗收

- 在 Mac 上核對主視覺、字體層級、留白、圖片清晰度、內容寬度、導覽及主要行動。
- 每個網站保留自己的品牌特色，共用元件、比例與操作方式保持一致。
- 每種頁面模式提供 Mac 與 iPhone 的截圖及操作證據，檢查首頁、內容詳情、表單、分享及錯誤狀態。
- 核對主日、講道、聚會、新朋友、聯絡等入口與內容；網站用途不同時固定適用的驗收清單。
- 質感評估使用事先固定的檢查項目與人工畫面審閱；未確認的視覺項目保持待驗收。

## 執行與交付

1. 固定驗收清單與共用畫面規格。
2. 優先處理登入、主帳號對應、權限與完整儲存。
3. 將共用元件套用至所有管理頁，再逐一驗收特有流程。
4. 執行自動回歸、iPhone 17 與 Mac 實機操作。
5. 每次交付附已通過／未通過／未執行清單、截圖、錄影及剩餘問題；通過發布門檻再正式更新。

實機尚未驗證的項目保持待驗收，不宣稱已達標。平台能力與原生 App 返回需求須以技術驗證決定後續實作方案。

# 生命樹讀經與靈修試閱回歸

使用 `tests/package.json` 鎖定的 puppeteer-core。安裝及執行：

```sh
cd tests
npm ci --ignore-scripts
npm run life-tree:browser
```

可設定 `CHROME_EXECUTABLE`；`TREE_TEST_OUTPUT` 指定證據目錄。預設結果放在被忽略的 `tests/life-tree/results/`。`PUPPETEER_MODULE` 可指定已安裝的同一版本模組路徑。

測試自行建立本機伺服器與獨立 Chrome profile，攔截所有 Supabase、LINE SDK、經文與天氣請求，使用虛構身分和資料；其餘外部請求封鎖。不登入真實 LINE、不寫入任何資料庫，不寄送通知。

驗證音樂偏好與實際原生媒體播放狀態／播放時間、啟動失敗重試、進度更新、讀到經文結尾、記錄和澆水的等待／重複點擊／失敗恢復、一月試閱與固定返回、手札草稿保留、挑戰、補讀日期、18人花園、切換競態、排行按需載入、320–1920 CSS px 版面、44px 按鈕高度、減少動效，以及經文失敗與逾時後重試。

澆水後的靈修入口另檢查：今日澆水成功後浮動提示立即可點，短螢幕與桌面仍可操作、輸入時收合、關閉與返回後不反覆提示，返回保留草稿與讀經紀錄。沒有樹圖頂端的大型永久入口，補讀其他日期不觸發今日邀請。

逾時測試只在隔離瀏覽器內將經文來源的15秒 timer縮短為100毫秒。正式程式仍為15秒。

音訊另檢查首次可信任點擊同時啟用音樂／音效、播放失敗與逾時恢復、音效單獨失敗、背景暫停、小喇叭重試、八個 WAV 解碼及 RMS／峰值、澆水成功後沿用已啟用的音效播放器。這些檢查不代表喇叭或藍牙實際發聲。

這些是 Chromium 模擬尺寸與合成資料的檢查；不能代表真實網路速度、可聽見的音量、iPhone LINE、Mac Safari或完整99%驗收。

首次說明另檢查：新瀏覽器先顯示全版說明，音效預設勾選且可取消；未勾選可正常使用，勾選本身不播放，按開始（含鍵盤Enter）才同步啟動原生音樂與提示音。選擇於同瀏覽器保存，重開不重複顯示；已選音效在下一次正常操作恢復。說明可從表頭重開，Escape關閉並恢復焦點；偏好儲存受阻不會卡住。320／402／1440px可捲到開始按鈕，音效勾選以完整label提供觸控範圍。

風雨提示另檢查：四類挑戰各自背景、提示與鍵盤前往照顧、失敗保留／成功還原、複數逐項處理、future與resolved不提示。健康樹不顯示道具；待照顧時，雨衣、噴瓶、兩人搭肩扶持與掃把圍繞樹邊，四個同時出現仍可點擊且不互相遮擋。44px小喇叭位於標題旁。風雨／照顧／讀經配樂依狀況切換，沿用同一個播放器。切換手機／桌面模擬會重載頁面，必須等待會員畫面完成後量測，並經可信任操作重新啟動聲音。

導覽與補讀另檢查：三個穩定入口、漏讀數量與日期／章節、七天期限、補讀讀到經文結尾才可送出、昨天準時讀經但未澆水的繼續路徑，以及過期日期不提供後端會拒絕的澆水按鈕。前往照顧可取消尚在等待的花園切換。

補讀日期框於320–1920px檢查四欄：第一列四天、第二列三天加其他日期下拉選單，日期框與選單維持44px操作範圍。下拉只列目前最近七天可補日期，不變更後端規則。

重開聲音回歸另模擬每個媒體元素的手勢限制與允許播放兩種政策：記得同意後自動嘗試、NotAllowedError不當成載入故障、一般文字touchend即可啟動（即使click被阻擋）、等待中的播放可即時接手、靜音保存及背景返回重用同一播放器。測試用Chromium允許native播放，再以隔離wrapper重現政策，仍使用真正WAV解碼與播放時鐘；不能據此推定iPhone／LINE的播放政策或實際喇叭出聲。

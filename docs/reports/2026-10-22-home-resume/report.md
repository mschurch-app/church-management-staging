# 首頁較早工作與 iPhone 返回修正

基準：7d5967bba977343e56f0ec24aa8f5475dd695ba4。使用者實機回報：較早工作佔住未排期區，離開再返回仍白屏。

## 原因與處理

首頁原本僅依 dueAt 分類，沒有期限的較早預告、字幕審核及舊測試全部留在「未排期」。本次僅改顯示分類：已知預告／講道審核工作可辨識標題中的完整有效日期，過往日期收至預設收合的「較早工作」；其他無期限且建立超過 14 天者也收在此處。明確有期限的未完成工作仍保留在逾期追蹤。來源信息日期不當作期限；未推定工作已完成、未刪除或改寫資料庫紀錄。其餘工作超過四項可直接展開，不再誤指到無日期工作不會出現的行事曆。

移除週曆底部重複的未排日期集合，避免共用行程因沒有 dueAt 被重複算入。返回後重新讀取安排；跨台北日期重新計算本週與今日。當次來源讀取失敗的既有提示保留。

前版恢復僅在 BFCache 返回或 DOM 內容消失時安全重載；iPhone 可能仍保留 DOM／layout，但畫面繪製面沒有恢復。因此改為普通 iOS 前景返回也在安全條件下重載原頁，並補上 blur/focus 及 pagehide/pageshow 路徑。保留未存表單、非表單編輯、執行中操作、浮窗、離線、付款／登入一次性返回保護；加上十秒防循環。沒有清除登入或重送任何業務請求。

一次性 sessionStorage 僅保存原路徑與捲動座標，載入後清除；功能分類寫入既有 center URL 參數。行事曆讀取改在恢復判定後進行，避免它自己新設的忙碌狀態擋住安全恢復。

共用 runtime／resume／PWA 與間接引用、首頁及 Worker 版號一致為 20261022-home-resume1，舊 query 使用目前來源以維持其他頁面相容。

## 驗證與限制

- 首頁模型 8 項 assertion 通過：來源日期、非法日期、其他業務標題不誤判、個人／協作範圍、真實逾期保留、原狀態不改。
- 本機 Chrome 的手機／桌面首頁 15 項通過；含 iOS user-agent 及合成生命週期的實際首頁模組重載、保留分類、避開行事曆競態。home-tests.json。
- 返回恢復 20 項通過；含普通返回、DOM 空白、BFCache、缺 visibility 的 blur/focus、草稿／操作／離線／回呼保護、一次性座標恢復與防循環。resume-tests.json。
- Worker 22 項、app-catalog、變更 JavaScript 語法、git diff --check 通過。已檢視合成首頁 390px 預覽；測試畫面不含真實個資。

使用者那台 iPhone 的實際 WebKit／LINE 表面問題尚未取得修正後實機證據，不能宣稱已完全消失。模擬 user-agent 與合成 visibility 事件不等於 iPhone 驗收。前次記錄的 phase3 週報按鈕遮擋及 phase2 definitions 固定數量問題仍未解決，不宣稱完整 quality-gate 或整體 99% 通過。

當次僅唯讀核對使用者指出的少量既有工作狀態；沒有將原始查詢資料存進提交。未修改 Auth/RLS、未對正式業務資料寫入、未發 LINE 或恢復任何智慧體排程。測試使用合成工作。

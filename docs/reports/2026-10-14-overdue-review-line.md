# 初審／複審逾時 LINE 提醒

2026-10-14 起，正式環境每 5 分鐘檢查一次已設定初審與複審人的流程。案件進入當前待審階段滿 2 小時且仍未審時，對該階段實際審核人加發一次 LINE 提醒。複審從初審通過、進入複審的時間重新起算。退回、核准或離開該階段後不再建立新提醒。同一審核人同一流程同一階段的多筆逾時案件合併為一則 LINE 訊息，避免舊案件洗版。

適用於有兩位審核人設定的講道 IG、每日經文，以及服事調整的影音、接待、兒童主日學流程；敬拜團設定缺少初審人，待補齊後自動納入。講道 IG 以尚未完成的審核任務指派為準；每日經文使用既有三階段流程中的鈺庭初審與師母複審，不把牧師終審混入這項兩階段提醒；服事調整使用實際有審核權的領袖與複審人。審核設定頁和實際指派仍有不一致，這項提醒依實際指派，避免送到無權審核的人。沒有 LINE 綁定的人不會假稱已收到。

資料庫用每個案件、階段、開始時間、收件人作唯一鍵；LINE 推播使用批次 UUID 作 `X-Line-Retry-Key`，同一批失敗重試不更換訊息。傳送前再次檢查案件是否仍在待審階段。資料表僅 service role 可用，cron 使用原有 Vault 祕密呼叫 Edge Function，未向瀏覽器開放入口。

正式驗證：cron job 24 `church-os-overdue-review-line` 已啟用（每 5 分鐘）。首次執行把 59 筆待初審每日經文合併成一則、2 筆待初審講道 IG 合併成一則；LINE API 接受兩則，資料庫記為 2 批 `sent`、61 個案件回條。立即再次執行回報 `sent: 0`，批次和案件數未增加。這是 LINE API 接受回條，不代表收件人已閱讀。正式環境本機缺少 Deno CLI；Edge Function v2 已部署且實際執行成功。審核人實機收件與未來複審新案需後續觀察。

再次查核時，cron job 24 於台北 13:55 已自動執行成功。新增送出前核對：若案件重新編輯、換階段、完成審核、審核權變更或設定不再完整，舊批次不會因重試而誤送。未帶 service role 的呼叫實測回 `forbidden`；以 service role 在交易回滾中執行候選查找，回報 0 個待補批次。

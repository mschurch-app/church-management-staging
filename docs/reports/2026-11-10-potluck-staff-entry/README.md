# 感恩美食大冒險：同工代登記料理（2026-11-10）

## 行為

活動管理頁上方新增「新增料理」。同工可替沒有LINE的人填寫家庭／提供者公開名稱、菜名、分類、份量（預設10，可直接輸入小數或較大份量），以及選填過敏原、保存／加熱需求、非公開同工備註。

只有既有M+ potluck管理權限或有效主帳號能新增；只有檢視／匯出權限者不能新增。公開登記截止後同工仍可補登，封存活動則禁止新增。

代登不建立LINE帳號、假LINE subject或會友名冊；以獨立活動提供者建立料理，標示「同工代登記」。不依同名合併家庭。既有料理清單、分類統計、管理編輯／取消與CSV都納入代登資料；CSV在末欄增加「登記方式」。一般LINE使用者不能把代登料理當成自己的資料。

## 寫入與失敗恢復

DB沿用每活動鎖、管理權限閘門與(event,actor,request_id)收據。料理、活動提供者與稽核同一交易完成。操作來源固定staff、owner_subject為null；操作者沿用由伺服器驗證的教會OS Auth身分。

新表單儲存時鎖定欄位，連按不重送。若結果不確定，保留相同內容及request_id，關閉浮窗再開也可繼續同筆重試。若已確認新增、但清單回載失敗，明確顯示已新增並要求重新讀取，不再次新增。瀏覽器離開時對未完成草稿給予原生提醒；草稿僅在目前頁面記憶體，不宣稱跨瀏覽器關閉恢復。

## 相容性與權限

新增registration_source（既有資料預設line），只放寬owner_subject以支援staff來源null owner，並以來源／owner一致性constraint保護。不變更既有菜的id、家庭、份量、日期、目標、狀態或LINE擁有權。沿用public.potluck_action簽名與既有私有potluck schema/RLS；不向anon/authenticated開放RPC或表格。admin_get多回傳由後端判定的can_manage，新增按鈕以此及封存狀態顯示可用性；後端再次檢查實際操作權限。

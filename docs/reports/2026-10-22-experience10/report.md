# 教會 OS 第十批：排班裝置草稿續填

基準：正式 main `a70bb963a4c78f2745d4ee4e01763e8d136637c0`（#242）。接續第七、九批記錄的「頁面被關閉後，未儲存排班續填」項目。本批只接入排班編輯表單，資料庫、既有儲存 API、登入及通知規則保持相容。

## 操作與保留範圍

- 預設不保留輸入。同工需點「在這台裝置保留草稿」，才在這個瀏覽器／App 的 IndexedDB 暫存聚會日期、主題與可見排班欄位。每次成功更新後可保留 24 小時；必須等交易完成，才顯示已保留。
- 重開時顯示「繼續填寫／刪除裝置草稿」。繼續填寫會帶回欄位並標記尚未送出，不會自動寫入正式排班。正式儲存失敗保留表單及草稿；成功後清除裝置草稿，清除失敗則另外提示，避免誤認正式儲存失敗。
- 草稿按伺服器確認的帳號、同一次登入的 session ID、堂會分開。同一次登入的 token 更新可沿用，重新登入或另一個帳號不能續填。JWT 的 session ID 僅用來區分裝置資料，不能授予權限；續填及恢復後送出前，重新確認現有 readAccess 與排班操作權，寫入仍經原有後端授權。
- 頁面收到登出／身分改變事件時立即隱藏編輯內容、清單及輸出選項，並清除舊 session 的裝置草稿。加入世代檢查，延遲完成的續填或清單請求不能在登出後重新顯示舊內容。
- 多分頁使用 IndexedDB 同一交易內的 revision 比較；舊分頁不能覆寫或刪除較新的草稿。停止保留、取消及開啟其他排班，都沿用相應的放棄確認或顯示清除失敗。
- 恢復前核對原排班內容及可見服事項目；原資料刪除、內容或欄位改變、同日已存在正式新增排班時，拒絕自動套用。恢復後送出也重新核對原排班與可見項目。發生衝突會保留裝置草稿及本頁輸入，不做自動合併。
- 瀏覽器空間不足、禁用儲存或裝置交易失敗時，清楚顯示未保留；原表單仍可編輯及使用既有儲存流程。搜尋、篩選及相同的 blur/change 不重寫業務草稿。

排班頁與浮動選人清單明確沿用共用系統字體，修正 Safari 原有根節點繼承規則導致的襯線字體。新增草稿區沿用現有表面色、字色、焦點及至少 44 px 按鈕。HTML、兩個草稿模組、排班樣式／模組與 Worker shell 版本一致更新至 `20261022-experience10`。

## 限制與待驗收

1. IndexedDB 是瀏覽器來源內的裝置資料，沒有額外加密；本批的帳號／session 分區不是抵抗同來源惡意程式或裝置管理者的安全邊界。介面提示共用裝置勿開啟，沒有宣稱加密保存。
2. 保留僅限同一瀏覽器／App 儲存空間、同一登入；Safari 與主畫面 App 等不同入口不保證共用。瀏覽器清理、空間回收、私密模式或系統在交易完成前終止程序，仍可能失去最新輸入。
3. 若排班頁在登出時已關閉，無法收到該頁的清除事件；舊紀錄在新登入下無法續填，但可能實體留在裝置直到到期後的下一次存取／清理。24 小時到期不是背景定時刪除服務。
4. 正式資料指紋核對與原有後端寫入是兩次操作，沒有新增伺服器端原子版本鎖；不宣稱完全解決核對與儲存之間的並行修改。原有日期唯一性與授權仍由後端處理。
5. 衝突草稿不自動合併，也未提供匯出；其他業務表單的關閉後續填仍待分批處理。
6. iPhone 17 主畫面 App、Safari、LINE 內開啟、系統終止、鍵盤／讀屏／弱網等實機項目仍待驗收。Mac Safari 這次只驗證本機合成流程，未驗證正式帳號的全部新流程；不宣稱整站實機達 99%。

交付狀態：程式與本機證據完成，等待本批公開儲存庫上傳及合併上線授權。未把本機完成當成已部署。

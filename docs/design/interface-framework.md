# 教會 OS 共用介面與設計框架

適用：教會 OS 所有新功能、新頁面及既有頁面修改，以及兩個教會網站後續的設計與功能開發。手機以 iPhone 17、桌面以 Mac 為主要基準；共用視覺規範，操作與版面依裝置適配。

此框架是後續開發的預設規範。既有共用元件與使用者核定的設計方向為起點；每次交付須依 [裝置與品質驗收基準](device-acceptance.md)記錄結果。99% 為驗收目標，核心流程必須全部通過。

## 視覺規範

| 項目 | 共用要求 |
| --- | --- |
| 整體 | 精緻、俐落、簡潔；資訊層級清楚，操作區穩定，通知以精簡摘要呈現。 |
| 字體 | 使用系統字體；沿用共用標題、內文、標籤與輔助文字層級。支援文字放大，重要文字與操作不截斷。 |
| 顏色 | 使用共用語意色：文字、次要文字、表面、邊框、主要操作、成功、提醒、錯誤。一般文字至少 4.5:1，大字至少 3:1 對比。 |
| 圖示 | 使用同一套自製 SVG，形狀、筆畫、背景、圓角與尺寸一致；以功能 key 對應，動態新增亦須套用。 |
| 表頭 | 同用途管理頁共用高度、配色、Logo 尺寸與操作布局。正常字體的現有高度為 164 CSS px；大字及特殊內容依共用規則調整。 |
| 卡片與表單 | 沿用共用圓角、邊框、留白及欄位樣式；每區有明確主題。長表單分步或分區，選填項目清楚標示。 |
| 按鈕 | 主要、次要、移除等動作有一致樣式；功能入口使用圖示卡片。主要觸控範圍至少 44 × 44 CSS px。 |
| 常用功能 | 每列三顆，長按排列；移除後仍在收納盒可找到並加回。 |
| 響應式 | 使用可用 viewport 與安全區域，避免硬套裝置實體像素。Mac 清單、詳情、表格與工作區依視窗寬度安排。 |

主要文字、次要文字、強調色、表頭高度、間距、圓角及圖示配色集中定義於 `app-design-tokens.css`；`app-consistency.css` 將變數套用到共用元件：`--app-ink`、`--app-secondary`、`--app-accent`、`--app-header-height`。調整共用設計時修改語意變數與共用元件，並檢查受影響頁面。

色彩與文字對比依 [W3C 文字對比準則](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)；觸控範圍參考 [Apple 設計建議](https://developer.apple.com/design/tips/)及 [Web 觸控範圍準則](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)。

## 兩個教會網站的呈現

兩個網站以 Mac 瀏覽時的精緻感與易讀性為主要設計基準，手機仍須在 iPhone 17 正常使用。與教會 OS 共用字體層級、色彩語意、間距、圖示風格及操作回饋，各網站保留其 Logo、品牌色與內容特色。

- 導覽清楚、內容有層次，主視覺、主題、副標與主要行動形成穩定的閱讀順序。
- 留白充足，長文限制閱讀寬度；大圖依主題選用，清晰且裁切合理。
- 陰影、透明材質、漸層與動效適量使用；文字對比、載入速度與操作可用性須符合驗收要求。
- 主日資訊、講道、小組教材、新朋友與聯絡等內容容易找到；不同用途頁面沿用同一套導覽與元件。
- 官網使用適合公開內容的頁面骨架；管理系統的固定表頭、權限入口與常用圖示布局，依管理用途適用。
- Mac Safari 與 Chrome 驗收視窗縮放、圖片呈現、連結、表單及檔案操作；iPhone 驗收安全區域、閱讀與觸控。

## 共用元件與程式接入

| 職責 | 現有共用來源 | 新功能的接入方式 |
| --- | --- | --- |
| 語意樣式 | `app-design-tokens.css`、`app-consistency.css`、`ios-experience.css` | 沿用共用樣式與 CSS 變數；頁面專屬 CSS 限於該頁工作內容，避免新的全域 button／文字覆蓋。 |
| 圖示與裝置互動 | `app-icons.mjs`、`ios-experience.mjs` | SVG 在 `app-icons.mjs`；功能對應在 definitions、配色在 tokens；保留安全區域、鍵盤、動態圖示及減少動效支援。 |
| 堂會品牌與相關導覽 | `church-brand.mjs` | 管理頁沿用共用表頭及堂會範圍；公開頁依用途安排導覽，保持同一套視覺語言。 |
| 完整功能入口 | `app-function-definitions.mjs`、`app-function-catalog.mjs` | metadata／分類／角色建議在 definitions，catalog 依既有權限篩選；新功能加入唯一 key、名稱、路由、分類、堂會及權限條件；確保搜尋、收納與常用一致。 |
| 功能與設定元件 | `app-ui.mjs` | 以 `createFunctionEntry`／`createSettingsEntry` 建立入口；導覽連結與加入／移除按鈕為並列控制，避免巢狀互動。 |
| 前端權限 | `admin-access.mjs` | 沿用既有權限判斷；另由後端檢查實際資料操作權。首頁捷徑只表示偏好。 |
| 資料請求 | `admin-db.mjs` | 管理頁沿用共用資料客戶端與期限；登入、錯誤及儲存由業務處理器呈現結果。公開頁只接入必要的服務。 |
| 操作回饋 | `action-feedback.mjs` 與頁面處理器 | 純導覽、開關浮窗與送出資料分清；完成提示依實際結果，逾時提供恢復方式。 |
| App 安裝與更新 | `app-pwa.mjs`、`church-os-sw.js`、`app.webmanifest` | 變更共用資源時統一版本；驗收已安裝 App 的更新、返回與重開。 |

表中的程式路徑為教會 OS 專案的共用接入點；兩個官網在各自專案使用其共用樣式與內容模組，逐步對齊同一套設計規範。第二階段已集中功能、路由、角色建議與圖示定義，首頁與設定區已沿用入口元件；既有各業務表單尚未全數改用新元件。後續改版維持既有登入、資料、堂會與權限行為。

## 標準頁面模式

- 清單：標題、搜尋／篩選、結果、主要操作及空資料狀態。
- 詳情：身分或紀錄摘要、分區內容及明確操作。
- 表單：欄位分組、選填標記、即時欄位錯誤、儲存狀態及取消。
- 引導式流程：顯示目前步驟，可返回修改，錯誤保留已填內容。
- 設定：依帳號權限、審核通知、內容發布及堂會場地歸類。
- 通知：摘要、未讀數與內容浮窗；歷史通知可翻閱，浮窗捲動不穿透背景。

功能需要不同工作區時，可依用途調整資訊密度與導覽，沿用字體、色彩語意、圖示及操作回饋；設計理由記錄在該功能文件。

## 操作與資料規則

每個操作均有按下回饋、等待狀態與實際結果。成功、失敗、取消與逾時都有下一步，失敗保留使用者輸入。移除等重要操作要清楚說明影響範圍。

表單明確指定按鈕 type，純介面操作使用 `type="button"`。非同步操作在完成或失敗後恢復可操作狀態；重試避免重複新增、寄送或發布。主帳號、堂會與權限對應須一致，關聯資料整筆儲存或回復。

浮窗管理焦點與背景捲動；Mac 支援鍵盤與觸控板，iPhone 支援觸控、長按與安全區域。動效不可阻擋操作，並尊重系統減少動態效果設定。

## 新功能交付流程

1. 選擇頁面模式，確認角色、堂會、路由、操作及失敗情境。
2. 接入共用元件、功能目錄與圖示系統。
3. 列出固定的驗收項目，記錄預期結果及必要裝置。
4. 實作功能並核對資料、權限及操作回饋。
5. 依已授權的測試範圍進行回歸與實機驗收；未驗收的項目保持待驗收。
6. 交付畫面、操作證據、通過率與剩餘問題；符合發布門檻後更新。

桌面與手機各自記錄驗收結果，不能以其中一種裝置的通過結果推定另一種裝置已通過。獨立課輔、籃球等其他專案導入此框架時，需於各自專案實作及驗收。

## 第四階段恢復與發布要求

更新 App 由使用者選擇時機；有未儲存內容或進行中的操作時保護內容。離線提供原頁重試，不自動重新送出資料。通知閱讀期間停止輪播。正常表頭高度與大字模式分別驗收；共用裝置行為依 `component-contract.md` 接入。

每次發布執行固定的登入、權限、資料、流程、版面、對比與 Worker 回歸，記錄來源版本、測試環境、結果和正式資源比對。效能記錄需標明資料、網路與快取條件；不能用合成資料的載入速度代表使用者實際速度。

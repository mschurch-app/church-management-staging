# 教會 OS App 整理、測試與改善報告

日期：2026-10-09　版本：20261009-app-audit2

## 結論

本次已修正功能入口遺失、管理員功能選擇器看不清楚、初審／複審設定入口缺漏，以及管理頁表頭高度不一致。功能收納盒改由完整的權限目錄產生，常用只是個人捷徑；從常用移除後仍可在收納盒找回。

LINE 登入新增跨瀏覽器的加密交接。外部授權完成後，回到原本安裝的 App，系統會接續登入；關閉後重開也會讀取尚未到期的交接。不再先開一個空白頁。這項修改已通過隔離瀏覽器測試，仍需實際 iPhone 驗證，不能宣稱已完成原生 App 的自動跳回。

本次沒有對正式資料執行管理員移除、邀請寄送、內容發布、付款或審核核准。現有歷史資料與權限沒有被批次重設。

## 功能與權限盤點

共有 41 個入口，每個入口只歸入一個收納分類。已在常用的功能不重複出現在收納盒；搜尋仍可找到。分類只改呈現，不授予新的後端權限。

| 收納分類 | 功能 | 顯示條件 |
| --- | --- | --- |
| 人與關懷（6） | 會友、新朋友、小組與小家、代禱與關懷、關懷訊息、同工工作區 | 各功能既有查看權限；同工工作區需既有指定入口。 |
| 聚會與服事（5） | 出席登記、服事安排、服事意願與協調、場地與設備、物品與借用 | 各功能既有查看權限；服事意願目前限 M+，依服事權限顯示。 |
| 內容與發布（9） | 生命樹、主日週報、小組教材、牧養圖卡、給今天的你、把愛傳出去、LINE 服務預覽、社群發布、字幕詞庫 | 依讀經、週報、教材或牧養權限；社群發布另需週報核准權，字幕詞庫需週報編輯權且限 M+。 |
| 課輔（7） | 課輔、課輔打卡、課輔安排、課輔出席、學生、個別輔導、課輔報表 | 需既有外部入口授權；資料操作仍由課輔系統判斷。 |
| 籃球事工（7） | 熱火籃球營、籃球隊、比賽紀錄、籃球戰術、球員作業、球隊行程、每日狀態 | 熱火籃球營需對應權限且限 M+；球隊入口需既有授權，操作由球隊系統判斷。 |
| 設定與工具（7） | LINE 身分確認、審核流程、通知設定、首頁與表單、同工帳號與權限、教會設定、系統狀況 | 依功能權限；帳號權限管理限專案擁有者；系統狀況保留獨立授權。教會設定只呈現可使用的工具。 |

另遵守個別功能的「查看」限制與明確停用設定。未授權功能不顯示；首頁偏好不再被當作完整的權限清單。舊代禱、關懷訊息權限名稱加入對應，避免已有授權卻找不到入口。

## App 登入流程

1. 從主畫面開啟教會 OS，點「LINE 登入」。
2. 開啟有內容的登入引導頁，再前往 LINE 授權。
3. 外部瀏覽器完成授權後顯示返回 App 的提示。
4. 回到主畫面點教會 OS，或用 App 切換器返回；原 App 驗證交接資料與使用者身分，接續進入首頁。
5. 連線失敗會顯示狀態並等待恢復；可取消。等待超過五分鐘會恢復登入按鈕。

目前是安裝到主畫面的 Web App。Apple 的 Web App 說明包含外部導覽進入 Safari 的情境，因此無法以網頁程式保證自動切回原 App；本次採原 App 恢復登入的方式。[Apple Web Apps 說明](https://developer.apple.com/videos/play/wwdc2023/10120/)

LINE 授權仍遵循既有 OAuth 回呼及身分綁定流程。[LINE Login 官方整合文件](https://developers.line.biz/en/docs/line-login/web/integrate-line-login/)

交接中的登入資料使用 AES-GCM 加密，伺服器只存密文；讀取須持有隨機交接密鑰，過期無法讀取。伺服器完成端另驗證 LINE 登入身分。成功後刪除交接；未消費的過期資料在下一次已驗證交接時清理，尚未增加定期清理排程。

| 資料庫權限 | 新交接表啟用 RLS，anon 與 authenticated 無直接讀取權；新增能力 RPC 僅回傳本人是否為擁有者。既有安全顧問警告數未增加。 |

對比以一般文字 4.5:1、大字 3:1 為門檻；計算涵蓋文字、背景與漸層端點，仍需實機觀察圖片背景、系統選單及所有動態資料狀態。[W3C 文字對比準則](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)

## 依商業 App 品質要求的改善建議

優先級：P0 為正式驗收前應完成；P1 為下一輪核心穩定性；P2 為後續整理。

| 優先 | 發現 | 建議與驗收條件 |
| --- | --- | --- |
| P0 | Web App 與 Safari 的登入狀態分開；實際 iOS 行為不能由桌面模擬證明 | 在一部真實 iPhone 檢查全新登入、取消授權、背景返回、App 重開、已綁定帳號與綁定流程。每條路徑都有結果、可恢復且無空白頁。若一定要自動切回 App，另評估原生容器與系統授權回呼。 |
| P0 | LINE 與 Email 帳號合併目前仍有同名判斷；不能可靠代表同一人 | 建立經驗證的 LINE ↔ 主帳號對應，審核後一人一筆。不得只依姓名刪除或合併；已有核准紀錄須先核對再遷移。 |
| P0 | 管理員儲存依序呼叫多個 RPC，可能部分成功 | 改為單一交易儲存帳號、堂會、權限與服事範圍；失敗整筆回復，並給明確欄位錯誤。移除管理權限也需明確主帳號與關聯身分規則。 |
| P1 | 部分共用操作提示依時間猜測下載／列印完成 | 每個業務操作由真正結果回報完成，逾時給重試；重試不能重複寄信、發布或登記。列印與下載要區分「已開啟」和「已完成」。 |
| P1 | 41 個入口與後端角色建議清單仍分散 | 合併成一份功能定義，包含堂會、查看、操作、分類與角色建議。入口與後端授權分別驗證，避免新增功能漏進收納盒。 |
| P1 | 會友 LINE 服務與管理登入是兩種流程 | 每日靈修、生命樹、服事登記分別用測試 LINE 帳號實機驗收；分清未登入、未綁定、未核准、無權限與服務中斷，提供對應下一步。 |
| P1 | 設定頁仍混合帳號、內容、通知與發布 | 保留單一設定首頁，分「同工與權限」「審核與通知」「內容與發布」「堂會與場地」。審核人的個人待辦與流程設定分開。 |
| P1 | 外部系統入口授權與操作權限分開管理 | 增加唯讀的個人權限摘要；由各系統同步可用入口，避免以捷徑存在推定完整操作權。 |
| P1 | 缺少持續的完整流程回歸 | 建立測試資料環境，涵蓋所有角色、堂會、保存／移除／邀請／審核／匯出及失敗分支。把本次手機寬度、對比、功能目錄與登入交接測試納入每次發布。 |
| P2 | 多層 CSS 與多個 UI 定義容易互相覆蓋 | 將顏色、文字、表頭、按鈕、浮窗整理成共用元件與單一設計變數。新增頁面必須使用同一套。 |
| P2 | 空資料、錯誤與無權限容易呈現相似訊息 | 每種狀態顯示具體原因與一個下一步；提供版本資訊與安全重新載入，避免使用者猜是否更新。 |
| P2 | 新交接資料的過期清理依賴後續登入 | 如需要嚴格的資料保留期限，加入定期清理並監測交接失敗率；持續避免記錄登入密鑰及完整 Token。 |

## 建議的日常操作動線

首頁看通知與常用；收納盒搜尋所有已授權功能；教會設定管理流程與工具。審核通知直接開內容浮窗，再前往對應審核頁，讀取歷史通知不必切換整個首頁。功能名稱以工作內容為主，權限、帳號及堂會等技術資訊只在設定與錯誤處理時呈現。

# M＋例行行程與工作指派（待核准正式套用）

## 使用者可見流程

首頁的「新增行程」旁增加「例行行程」，主管另有「指派工作」。2026-10-22 起，具有既有行事曆權限的 M＋同工首次進入會開啟三步引導：工作內容、重複時間、負責與協作同工。逐項儲存後選擇新增下一項或結束；結束提醒日後可從例行行程繼續。明確選擇目前沒有例行行程也可完成首次設定，避免被不適用的必填卡住。

例行時段以 Google 原生 RRULE 同步到既有 mbot 共用行事曆，保持參與同工姓名。首頁可對單次行程完成回報或取消；停止整個系列另有操作，截斷未來重複、保留歷史。每月 29–31 日在缺少該日期的月份略過；初次時段遵循原有工時規則，後續重疊須由同工查看行事曆。

主管（既有 pastor/admin 權限）填名稱、完成標準、負責人、協作同工及必填完成期限。工作沿用 pastoral_tasks，按到期日顯示於本週行事曆，承接後可回報進度／完成；建立者或主管可取消。使用現有通知路由和 00:00–08:00 靜音排隊規則，回條如實顯示送達、排隊或失敗，失敗可重試。未建立額外背景智慧體或排程模型運算。

## 資料與安全

新資料僅存四張 service-only 表：mplus_work_routines、mplus_work_onboarding、mplus_event_reports、mplus_work_notifications。全部啟用 RLS，anon/authenticated 無直接存取，既有後端服務驗證身分與 M＋範圍後才操作。工作指派沿用既有 pastoral_tasks、pastoral_task_reports。

未刪除舊資料，未更動既有通知表約束，未擴大同工角色。Google 寫入以固定識別碼去重，未確認的儲存保留原內容與編號重試；單次回報禁止對重複母事件操作。回報先保存待同步意圖，成功後才標記同步完成。通知回條獨立存放，重用正式現有通知函式及夜間規則。

另修正正式行事曆來源中遺漏 UUID 常數、工時欄位型別守衛兩項檢查缺漏。

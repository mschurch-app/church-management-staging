# 奉獻自動加總及雙人點收確認

使用者要求主畫面的總額由每筆奉獻自動加總，兩位點收同工都確認後才可送複審。總額改為唯讀，由明細每筆總額計算；資料庫獨立重算各分類金額，不採信前端傳入的總額。原本每筆總額與分類加總的核對仍保留。

儲存後，兩位指定點收同工各自登入，只能勾選自己的確認；保存 canonical 身分、確認時間及稽核事件。兩人均確認前送審鈕停用，資料庫交易也強制阻擋繞過 UI 的送審。版本鎖防止同時確認或過期頁面覆蓋。任何重新儲存、明細或指定人員變更、退回都清除確認；修改中的畫面即停用送審。提供重新讀取確認按鈕，避免另一位完成後仍停留舊狀態。師母核對現金及牧師核准流程維持原順序。

確認請求的操作者從已驗證 JWT 取得，不接受前端代填 actor。RPC 僅 service_role 可執行；既有 JWT 檢查、RLS 及財務角色維持。確認或儲存進行時表單 inert 並標記 aria-busy，避免操作途中內容被覆蓋。

測試：PGlite 整合包含雙人本人確認、少一人阻擋、非指定人員、過期版本、假造確認資料、修改與退回失效、取消確認、儲存失敗回滾及 RPC 權限。既有資料庫、帳號及純函式回歸共 10 項通過。Chrome 隔離手機及桌面各 10 項互動通過，既有財務瀏覽器與權限儲存回歸通過，Worker 22 項通過。未宣稱真實 iPhone、Safari 或 99% 完整驗收；未代替使用者確認、送出或新增正式奉獻資料。

部署：cash_counter_confirmations 遷移已套用，finance-cash Edge Function v3 已部署並維持 verify_jwt=true。唯讀確認資料庫送審閘門、自動重算總額及僅 service_role 執行新確認函式；未新增業務資料。

# 主日講道字幕辨識與校對 SOP

本文件是 M+ 大雅教會主日講道字幕的固定作業標準。後續每週字幕都依本流程處理；若需要調整規則，應更新本文件並留下原因。

## 目標與優先順序

1. 忠於講員實際說出的內容，不摘要、不補寫、不改變講道論點。
2. 人名、經文章節、聖經與教會專有名詞正確。
3. 時間碼跟聲音同步。
4. 繁體中文斷詞與每行長度容易閱讀。
5. 通過品質檢查後才更新 YouTube 字幕。

正確性優先於追求一次完成。斷行規則可以持續累積，但不得為了版面漂亮而改變講員原意。

## 固定流程

### 1. 剪出講道正片

- 移除講道前的敬拜、報告與其他內容。
- 起點從講員正式開始講道算起，終點到講道結束。
- 記錄講題、講員、主題經文、講道日期與影片 ID。

### 2. 在本機辨識並保留字級時間碼

- 使用本機語音辨識產生初稿，並保留單字或短句時間碼。
- 目前可接受基準為 `faster-whisper` base 加上 word timestamps。
- 新模型要先以相同的五分鐘片段比較錯字、漏字、重複與幻覺。模型較大不代表這類現場錄音一定較準；測試未勝過基準時，不更換正式流程。
- 本機辨識時間碼是唯一時間基準，後續語言模型不得重寫時間碼。

### 3. 每五分鐘做一次完整上下文校對

- 每個片段約五分鐘，整段送入校對，不逐句孤立處理。
- 校對輸入一定包含講題、講員、經文與已確認的字幕知識庫。
- 校對項目包含同音錯字、漏字、重複口語、標點、聖經人名地名、章節、神學與教會用語。
- 每個原始編號必須回傳一次，筆數與順序不得改變。
- 校對模型只改文字，校正後文字重新套回本機原始時間碼。

### 4. 套用教會字幕知識庫

知識庫只收錄已經人工確認或已正式發布的內容，分成四類：

- **固定詞彙**：講員姓名、教會名稱、事工名稱、聖經書卷與常見專有名詞。
- **誤辨識對照**：例如「福市 → 服事」、「礦也 → 曠野」。
- **講員用語**：特定講員常用且已確認的說法。
- **已核准範例**：正式發布過的原始辨識與校正版，作為下一次同類內容的參考。

每次字幕正式核准並上稿後，系統將該次校正版與來源記錄到教會 OS，供日後人工整理與追溯。下一次自動校對只載入已確認的詞彙、錯字對照與講員用語，不會把過往完整講道再次送到外部校對服務。未經確認的模型輸出不得直接成為學習資料。

同工從教會 OS 的「系統設定 → YouTube 字幕詞庫」逐集處理：

1. 系統比較原始辨識與校正文字，整理成「待確認」錯字詞組。
2. 同工選擇講道集數，校正「辨識成」與「應改為」。
3. 確認正確後勾選「已由同工確認」並儲存。
4. 已確認且啟用的詞彙才會供下一次自動校對使用。
5. 不再適用的詞彙改為停用，保留來源與歷史，不直接刪除。

這是教會 OS 自己管理的校對資料庫，不是讓外部公用模型永久記住教會資料。完整核准稿保留在教會 OS 內；只有經確認且有助於校對的詞彙與錯字對照會加入校對提示。所有資料都可追溯來源、停用或修正。

### 5. 依語意重新分段與斷行

- 優先在句號、問號、驚嘆號、逗號等語意停頓處切分。
- 中文使用 `zh-TW` 斷詞；姓名、教會名稱、英文名稱與聖經詞彙視為不可拆開的單位。
- 每則最多兩行，每行最多 16 個字元。
- 不把英文名稱拆散，例如 `GOOD TV`、`MIS 工程師`。
- 片段只在附近時間範圍內重新分配，不能把後面的內容提前，也不能製造字幕重疊。

### 6. 自動品質閘門

全部條件通過才可進入發布：

- 每行不超過 16 個字元。
- 每則不超過兩行。
- 字幕之間沒有時間重疊。
- 每則至少 0.8 秒，最長不超過 12 秒。
- 閱讀速度不超過每秒 11 個字元。
- 已知錯字與舊誤辨識詞為 0。
- 所有片段皆完成，沒有缺少編號或空字幕。

任何一項失敗，都保留舊的 YouTube 正常字幕，不覆蓋正式版本。

### 7. 必看人工抽查點

- 講員姓名、教會與機構名稱。
- 主題經文、章節數字、聖經人名與地名。
- 英文、縮寫與專有名詞，例如 `GOOD TV`、`MIS 工程師`。
- 連續重複、停頓或情緒強烈處；口語遲疑可整理成「我……」，但不可刪掉實質內容。
- 開場第一分鐘、每個五分鐘交界及結尾祝禱。
- 字幕與聲音同步，尤其是曾修改過的句子。

### 8. 發布與回復

- YouTube 字幕使用獨立審核流程，不與 Instagram 發布綁在同一個按鈕。
- 直播影片隔日可編輯後，先在審核頁確認「保留完整直播」或「已剪除講道前內容」。
- 若已剪除敬拜與報告，填入實際剪除秒數，系統會在上稿前統一校正字幕時間碼。
- 完整校對與品質檢查通過後，更新 YouTube 的 `繁體中文（教會校對）` 字幕軌。
- 新字幕準備完成前，保留目前正在服務的字幕。
- 發布後再次確認 YouTube 字幕狀態為 `serving`，並記錄字幕 ID、則數與發布時間。
- 若發布後發現重大錯誤，修正後重新跑品質檢查再更新；不可直接用未檢查版本覆蓋。

## 持續改善原則

- 斷行不理想時，新增「正確斷法」範例或保護詞，不任意放寬字數與速度限制。
- 發現新錯字時，確認正確原音與上下文後再加入誤辨識對照。
- 同一問題重複出現時，修改自動規則並補記本文件，避免只修單支影片。
- 每次更換辨識或校對模型，都用固定片段與現行基準比較後才採用。

# 行政改善第一批：集中待辦與請假同步恢復

本批實作行政盤點的第一批：行政工作台、異常／逾期提示、財務入口與已核准請假行事曆同步恢復。沿用原單、原登入及原業務權限，沒有另造待辦資料庫，沒有自動核准、標記付款、改寫財務金額或代替代理人同意。

## 使用方式

M+首頁 → 行政 → 待辦與結案 → 行政待辦。工作台分待我處理、我送出的、已核准待完成、異常與逾期。按既有權限讀取請假、支出、收據草稿、待審場地及未還物品；可依業務及文字篩選，開啟原單。原單頁支援受原權限保護的紀錄連結。財務區新增奉獻回報及專案／事工入口。

工作台讀取上限會顯示提示：請假500、支出500、收據各類最近200、場地500、借還500。來源失敗不顯示為零待辦；結果只代表已成功讀取範圍，不聲稱完整年度／全歷史。請假等待3天與支出等待7天僅提示追蹤，不替教會設定法定或內部截止規則。可見資料不等於有審核／付款權；最終操作仍由原API驗證。未新增付款或收據發行行為。

## 同步恢復

每小時15分，以既有安全內部憑證檢查一筆已核准且pending／failed的M+請假，按最近嘗試排序；不碰待代理／待主管或其他單位。先GET既有Google事件，核對請假識別碼、日期／時段與重複規則，再必要時POST固定事件ID；409後讀回核對。已儲存事件消失、遭取消、日期不同或識別碼衝突時保留失敗供主管處理，不直接覆寫或重建。失敗不把其他並行作業的synced狀態改回failed。新增最近嘗試及安全錯誤代碼，不保存Google憑證至業務表。

正式補救請求208743回傳HTTP200、未逾時、synced。原本長期pending的一筆請假於2026-11-16T07:21:35Z更新為synced，核准狀態保持approved。未改另一筆等候代理人申請，亦未重送LINE。後端正式v27，五份部署來源讀回與測試來源一致。

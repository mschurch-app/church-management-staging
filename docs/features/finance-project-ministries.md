# 專案、事工與財務項目

擁有者於行政的「專案與事工設定」，或收據頁「設定專案、事工與收入科目」進入。設定區亦提供同一入口。

- 先建立專案，再於該專案新增多個事工項目。
- 新增事工時，同一交易建立收入科目與教會 OS 線上捐款項目；科目名稱可調整，代碼可留白稍後設定。
- 各項使用穩定的關聯 ID，更名不會改動已儲存收據的分類快照；停用不刪除歷史資料。
- 收據先選專案、再選事工，後端取得真正名稱與對應科目，不採用客戶端自行填寫的分類。
- 舊收據保留原有文字，可沿用或在草稿選擇新的分類；已開立者仍鎖定。收據會計 CSV 追加專案、事工、科目名稱、科目代碼與既有捐款項目編號。
- 籃球營沿用現有 camp_registration.events 的專案與捐款項目 172，對應資料唯一。原付款、收據與 eOffering 匯出路徑不修改。設定頁不能覆寫外部平台編號。

「線上捐款項目」在本功能指教會 OS 財務內的項目清單與對應，不會於 eOffering 新建外部募款專案或付款入口。

安全：既有已驗證的收據 Edge Function 取得 actor，使用 service-only RPC。管理操作限系統擁有者；前端隱藏不能代替後端檢查。私有 finance 表均啟用 RLS，未開放瀏覽器直接存取。請求 ID 去重、版本檢查及整筆交易避免重試重複及部分寫入。

驗證：隔離 SQL／Edge／CSV 14 項測試；Chromium／WebKit 在手機寬度 393px 與桌面 1440px 的合成流程驗證專案、子事工、收入／捐款清單及收據兩層選擇。Worker、功能目錄與 metadata 指定品質檢查通過。未宣稱真實 iPhone 驗收或完整歷史測試套件通過。

資料庫及 Edge v2 已套用；正式回查確認專案、事工、收入科目與捐款項目成對，籃球營保留唯一既有 172。安全檢查僅新增私有表「RLS 無直接存取 policy」的 INFO；這是 service-only API 設計，並已撤銷瀏覽器表權限。

## 金錢收據收入方式（2026-11-05）

手動新增金錢收據時必選：現金、轉帳、信用卡（藍新）、超商條碼（藍新）、虛擬ＡＴＭ（藍新）、ＬＩＮＥ ＰＡＹ（ＬＩＮＥ）。資料儲存、重開、預覽與會計 CSV 使用相同代碼／顯示名稱。

舊紀錄保留 NULL，呈現「未登錄」，不批次推定現金；既有未知方式的草稿可保留未知。物品收據不適用。此欄位登錄收入方式，既有付款訂單與營隊編號不變。

驗證：17 項 SQL／Edge／CSV 測試，以及 Chromium／WebKit 的 393px、1440px 合成操作（選擇、儲存、預覽）通過。另覆蓋開立單位設定、正式開立後會計匯出及舊草稿保留未知方式；修正開立單位 upsert 誤帶收據分類欄位的既有問題。

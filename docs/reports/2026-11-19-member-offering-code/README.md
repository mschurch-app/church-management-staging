# 會友奉獻編號呈現與後續個人奉獻查詢規劃

## 本次範圍

LINE 已完成會友綁定後，在會友建檔更新的個人資料卡顯示本人的四位奉獻編號；未配號顯示「尚未設定，請洽財務同工」。編號為只讀，不加入自助修改欄位，也不在姓名候選搜尋、待審身分或 onboarding 回應揭露。

後台會友名冊卡片與編輯表單顯示只讀奉獻編號。牧師、師母、鈺庭、恩茹列入明確的核心查看名單；財務會計沿用既有有效財務角色（含 accounting 工作分派的 entry）。一般會友管理員即使可以讀名冊，亦不會取得編號。財務會計若沒有名冊權限，仍從原財務登錄搜尋會友查看，不因此開放完整名冊、牧養備註或編號修改權。

不配發、不重編、不合併奉獻編號，不調整歷史奉獻、收據與會友資料。

## 權限設計

- `finance_member_codes` 仍不允許 anon/authenticated 直接 SELECT。
- `list_member_offering_codes` 是窄範圍只讀 RPC：必須有 auth.uid、有效且未停用的 M+ 帳號，以及核心名單或既有有效財務角色；最多100個 ID，只回 M+ 會友的 member_id 與 offering_code，不回金額、備註或 LINE 身分。權限不符只回 can_view=false 與空陣列。
- RPC 使用 SECURITY DEFINER 的理由：跨越私有財務表讀取兩個必要欄位，避免把整張財務表授權給瀏覽器。固定空 search_path、撤銷 PUBLIC/anon EXECUTE、對每次呼叫檢查 auth.uid 與當前帳號/角色。核心名單為私有 RLS 表，瀏覽器無存取權。
- 自助端沿用已驗證的 LINE subject → active binding → member_id 查詢，瀏覽器不能傳 member ID；原 service-only SQL reader 維持 invoker、空 search_path 及 service-only EXECUTE。Edge 白名單只新增 offering_code，12個依賴全保留，verify_jwt=false 維持既有自主 LINE 驗證。
- 資料仍不進入 Service Worker 離線快取。隱藏頁面與切換帳號沿用原本清除/重新驗證機制。

## 隔離驗收

PGlite 合成資料：四核心與會計可讀、一般同工/匿名/停用帳號/撤銷財務角色不可讀、跨堂會隔離、超過100個 ID 拒絕、LINE 本人只回自己的編號、無編號與封存/撤銷綁定、ACL 不放寬。

HTTP：已綁定才回編號、待審不回、任意 memberId 拒絕、修改 offering_code 拒絕、onboarding 不回會員資料。

Chrome/WebKit 各393與1440尺寸：個人卡顯示0028且無編輯輸入欄、原資料確認/失敗保留/相同要求重試正常；後台名冊顯示編號及尚未設定、權限撤銷後不再呈現，既有 LINE 文案與送出防重流程仍通過。Worker27項通過。

以上是隔離瀏覽器與合成身分驗收，不等於真實手機 LINE 實機已驗收。沒有建立正式測試會友、奉獻或推播。

## 正式讀回與回退

部署順序為資料庫加法變更 → member-access v33 → 前台發布。Edge全12個檔案讀回相符；只有 HTTP profile 白名單新增欄位。正式名單4人；既有6筆奉獻編號、196筆會友在本次操作前後不變。現有已綁定且有編號的一筆資料，使用 SQL 綁定查詢讀回與主檔編號相符，沒有輸出個人資料。

安全 advisors 新增兩個可預期提示：私有核心名單無瀏覽器 RLS policy（刻意拒絕存取），以及 authenticated 可呼叫窄範圍 SECURITY DEFINER RPC（上述逐次驗證）；沒有新增匿名可執行函式。

如需回退，先切回前台版本，再還原 member-access v32 與原 get_verified_member_status 定義；撤銷新增 reader 的 authenticated EXECUTE 即可停用。保留奉獻與會友主檔、核心名單，不刪除帳務。原 Edge 與 SQL 定義備份在工作區 local-operations/member-offering-code-20261119/。

## 後續「我的奉獻資訊」提案（尚未實作金額查詢）

LINE 家人登錄 → 我的資料 → 我的奉獻資訊。個人卡直接顯示自己的奉獻編號；入口進入財務資料時另做本人驗證，不將奉獻編號視為密碼。

畫面採年度切換、年度已確認入帳總額、依日期排列的明細與收據狀態。每筆顯示日期、奉獻分類、金額、方式及「已回報／待核對／財務已確認」；年度合計只計入財務已確認資料，退回/沖銷另註明，避免重複計入。收據只顯示是否申請、待開立或已開立，下載需另做短效授權。

建議分層：編號免額外密碼；金額與明細首次使用設定獨立查詢驗證，不採生日、手機末碼、奉獻編號作為密碼。優先評估傳送到已確認本人聯絡方式的一次性驗證碼；缺乏可信聯絡方式時先由財務核對身分。若採六位查詢 PIN，必須雜湊存放、登入失敗限次/冷卻、重設需重新驗證，不能由同工看見原 PIN。

驗證通過給短效查詢時段，閒置或背景後重新驗證；不在 LINE 通知直接揭露金額。跨裝置只依後端已驗證身分判斷，所有列表/合計/收據由後端限定 member_id，不接受前端自行指定他人。歷史僅有姓名或手填編號的資料先交財務核對，不因同名而自動歸戶。

完整查詢的驗收必須包括：跨會員越權、未綁定與撤銷綁定、PIN/OTP限次、共享手機、200筆以上分頁、沖銷/退回、收據下載與會員歸戶正確性。須先完成資料歸戶盤點，才能把金額開放給會友。

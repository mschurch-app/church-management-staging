# 課輔薪資：逐人簽到表、審核與匯款彙整（待正式套用）

行政／課輔薪資的「班表安排」已由 PR #294 合併上線；正式三個核心模組讀回 SHA 與已測試來源一致。只有固定綁定的鈺庭、恩茹取得排班操作入口及既有後端寫入權。

本次追加內容已實作及本機驗證，正式資料庫變更的工具確認兩次逾時，尚未套用；新版 API、月底重試服務及薪資前端尚未部署。沒有送出真人薪資審核或 LINE 測試通知。

## 行為

- 薪資人員由當月所有班次取得，不以 users.role_type 篩掉已有班次的人員。既有 T 編號老師雖分類為同工，也會列入。依使用者現有全員時薪 200 指示，僅為目前班表上缺少費率的人員補明確的 2026-11-01 生效紀錄，保留既有費率。
- 每人可開啟本月班次、看排班負責人、拍照或多選上傳簽到表、儲存、逐人確認。簽到原圖沿用 Google 共用根／教會ＯＳ系統資料夾／財務會計類／每月老師簽到表／年度／月份，不落 SSD。
- 班次安排者由現有操作收據回溯；新的新增或修改在服務端記錄安排者。共同安排的人員需鈺庭、恩茹各自上傳圖片並依序確認。沒有安排者紀錄的舊班次標示待核對，要求兩人確認，不猜測安排者。
- 第二位可直接看到第一位的圖片；師母預設展開全部人員及圖片。所有圖片限制於卡片及視窗內，牧師不載入簽到表。
- 每個人均有本階段確認紀錄。師母全員確認後，才能按「審核通過撥款」。班次變動或退回會使相關確認失效，不能沿用舊版本；恩茹修改班次後須退回鈺庭重新確認。
- 可先準備當月簽到表；月底最後一天台灣 21:00 才結算、通知並開放整月送審。準備動作不提前送通知。
- 牧師、師母的每人設定含生效時薪、匯款銀行與完整帳號。一般排班者不取得銀行帳號。舊頁面不可覆蓋新銀行資料；銀行變動要求重新核對。
- 師母通過後，依服務端核對資料產生單張 PNG，含每人時數、時薪、金額、銀行、完整帳號及合計。圖表存於現有私有儲存空間；LINE 僅向既有牧師綁定發送文字及短效圖片網址。即時動作與排程重試共用同一版本的發送邏輯。核准不代表實際銀行已轉帳。

## 驗證證據

- 新增 SSD 本機 PostgreSQL WASM 測試環境 PGlite 0.5.15，固定版本與 lockfile。完全隔離，只有假帳號與假銀行資料，不修改正式認證函式。
- 實際 SQL migration 編譯與三人流程通過：被漏列老師、時薪 200、共同安排者追溯、前後階段各自照片、逐人與全員閘門、月末時間閘門、銀行缺漏與舊版本、私有圖表與帳號隔離、退回失效、修改班次後重新計算。
- 393／1440 寬隔離 Chromium：每人多張上傳帶正確 worker_id、前人圖片內嵌且不出框、師母全員確認閘門、只有兩位薪資管理者有銀行欄位、實際生成 PNG 含銀行及帳號、牧師只見撥款圖表。所有請求均攔截。
- API 測試：完整 v29 基線語法保留、私有不可覆蓋圖表、圖片格式與大小、版本核對、權限拒絕、Google 上傳綁定人員、假 LINE 接收者含圖片訊息；沒有真實外部傳送。
- 未執行真人簽到表上傳、真實銀行帳號輸入、iPhone／Mac Safari 實機流程，不宣稱整體 99% 驗收完成。

## 正式套用及恢復

確認後先比對受影響正式函式與保存基線，套用 docs/migrations/payroll-per-person-review-bank-transfer.sql，讀回驗證所有個人與總計，再部署 mschool-api 及 school-payroll-cron 的完整依賴，最後更新前端與 Worker。不得在資料庫未就緒時合併新前端。不得以舊 API 的暫時相容性跳過新個人審核閘門。

恢復時保留所有新表、銀行紀錄、審核收據及 Google 原圖，不刪除真實資料。不恢復會將 transfer_snapshot 原封回傳一般排班者的舊查詢。若新流程出錯，可先恢復前端／API 基線並保留新的伺服器審核閘門，使未完成核對的撥款保持阻擋，再修復；課輔點名等其他 API 保留原 v29 行為。原正式來源與工具回覆保存 SSD，非正式資料備份不含真人原圖或帳號。

本機重跑：

```sh
node tests/payroll-person-db.cjs
node --experimental-vm-modules tests/payroll-person-api.cjs
node tests/payroll-person-ui.cjs
```

新機器可先在 tests/payroll-sql 執行 npm ci，或以 PAYROLL_PGLITE_PATH 指定已安裝的固定版本；本機套件與快取放 SSD。UI 測試使用既有 SSD Chromium／Playwright，沒有安裝或啟動 WebKit。資料庫測試只在記憶體內使用假資料；正式 Supabase 連線不在測試程式中。

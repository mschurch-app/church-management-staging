## 產品理念
「一家一道菜，讓愛滿出來！」在 LINE 官方帳號內透過 LIFF 開啟可愛、溫馨的感恩料理蒐集遊戲。前台呈現料理募集、可愛小熊主廚、料理圖鑑與祝福卡，後台則由教會 OS 活動管理統計及管理。不是獨立網站；應設計為可重複使用的 potluck 活動類型。

## 視覺規格與畫面
手機優先，奶油白 #FFF2DF、南瓜橘 #C56A36、深棕 #7E3F21；圓角卡片、楓葉、小熊主廚、可愛食物圖示、輕量成功動畫，繁體中文，適合長輩。視覺參考為本次 ChatGPT 對話產生的兩欄設計圖（左：首頁；右：登記料理）；**圖片尚未提交到此 repository**，需由使用者在 Codex 對話中附圖或另行匯入。不得宣稱已取得圖片。

### 畫面 A：活動首頁
頂部 M+Church、標題「感恩美食大冒險」、11/22（日）、副標「一家一道菜，讓愛滿出來！」；六類料理進度卡（主菜/肉類、蔬菜/配菜、飯麵/主食、湯品、甜點/水果、飲料），各顯示已登記道數/目標道數；餐桌插畫隨報名逐漸豐盛；主要 CTA「我要登記一道菜」，次要 CTA「看看大家準備了什麼」。達標仍可登記，顯示「豐盛加倍」。
### 畫面 B：料理登記
家庭/提供者顯示名稱、料理名稱、料理分類、份量預設 10 份（可增減及直接輸入，允許超過 10）、備註、過敏原、保存加熱需求、選填照片。按「登記我的料理」，防重送及錯誤提示。
### 畫面 C：料理圖鑑
料理照片/分類預設插圖、名稱、提供者公開暱稱、分類與份量；可搜尋及分類篩選，不顯示 LINE userId 等隱私資訊。
### 畫面 D：我的料理
查看、編輯、換照片、調整份量、取消登記；受截止時間與權限約束。
### 畫面 E：登記成功
「料理敲碗成功」、專屬料理卡、「感恩小廚神」徽章、分享至 LINE（SDK 支援時）。無排名、無付費、無競爭性評分。

## 業務規則
- 每個家庭原則上一道料理，後台可核准額外料理；不可單靠暱稱辨識家庭。
- 每道菜預設 10 份，允許更高份量，無業務上限；避免誤把類別總份數當成完整供餐人數。
- 不限制家庭總數；前台**不得顯示預估總用餐人數**。
- 預設目標：主菜 7 道、蔬菜 7 道、主食 7 道、湯品 7 道、甜點水果 7 道、飲料 7 道，共 42 道；目標可在後台調整，達標不封頂。
- 只有有效報名計入統計；取消後即時更新。
- 活動日期 2026-11-22，時區 Asia/Taipei；報名開關、截止與可編輯期限由後台設定。

## 教會 OS 整合
在既有「活動管理」新增「互動料理募集 / Potluck」活動類型，沿用現有活動主表、RBAC、API、部署、UI 技術棧。管理頁包含活動設定、分類/目標設定、料理列表、分類與份量統計、過敏原提醒、編輯/取消、CSV/Excel 匯出、LIFF 預覽、QR code、封存與可複製範本。不要另起獨立管理後台。

## LINE LIFF
先盤點既有 LINE 官方帳號與 LIFF 設定。LINE SDK 初始化與授權，後端驗證 token；不得信任前端 userId；敏感金鑰不得進入前端。LINE 身分與教會會員身分可選擇安全綁定。提供 LIFF 活動連結及 LINE 分享選擇器（依 SDK 能力與權限），從 LINE 圖文選單、活動訊息或群組連結進入。需測試 iOS/Android LINE 內建瀏覽器。

## Supabase 資料設計
先檢查既有 schema，優先擴充，不重複建表。可考慮 potluck_event_settings(event_id, default_servings, registration_open, registration_deadline, allow_user_edit, theme_config)、potluck_categories(event_id,name,icon,target_dishes,sort_order)、potluck_dishes(event_id,category_id,owner_user_id,display_name,dish_name,servings,image_path,notes,allergen_info,storage_requirements,status)、potluck_badges(event_id,owner_user_id,badge_type,awarded_at)。所有欄位/名稱以既有架構適配。必須有 FK、索引、RLS、授權、圖片 Storage 權限、稽核紀錄、防重送與並行保護。一般使用者只可改自己的資料；公開圖鑑使用最小化公開欄位。

## 安全執行順序
1. 先核實目前 Codex 使用的 repository、分支及現有教會 OS 活動管理架構。
2. 提交現況盤點、預計修改檔案與相容性/回滾方案。
